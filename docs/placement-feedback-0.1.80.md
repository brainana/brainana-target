# Placement failure feedback (0.1.80)

Position now uses one shared diagnostic model for chamber-based and direct-entry electrode placement. When no candidate is usable, “Why placement failed” lists each observed rejection type, the current limiting parameter values, practical review steps and controls that open the relevant specification or planning panel. The first issue's parameter details are expanded; others remain compact.

Reach feedback distinguishes the selected shaft's physical total length, reserved length above the insertion plane, usable length, permitted insertion interval and sampled required depths. If every sampled approach is too deep, it reports the numerical shortfall. For a Plexon U-Probe, the links open Tip to connector length and Reinforcement tube length in the isolated configuration dialog. Other families use their shaft/individual-length and reserved-shaft controls. Chamber height and guide-tube distal-end depth are included when applicable. The full shaft drawn in 3D is explicitly distinguished from the part available for insertion. Cable length and channel count do not increase reach.

Other diagnostics cover target requirements and point tolerances, device footprint versus chamber bore, guide-hole/shaft/tube diameters and grid seating, rim support and surface quality, named hard avoidance constraints and clearance margins, other chambers and linked electrode requirements. If no candidate reached evaluation, sampling/coverage is shown instead of inventing a reach failure. Point display radius is identified as visual only. Direct-entry feedback omits chamber-specific depth controls.

Search evidence records named obstacles and their best observed clearance, nearby other chambers/linked devices, and the closest rejected target miss. “Best clearance” for different objects may come from different candidates. Aggregate counts are explicitly the first failed check per candidate; later checks may not have been reached. Existing rejection order, feasible-candidate ranking and hard constraints are unchanged. Obstacle evidence reuses clearance calculations; it does not repeat expensive surface-distance checks.

Review buttons open the existing hardware draft or navigate to the appropriate feature and reveal/focus the control. Hardware values are not changed by following a link. Applying a hardware draft remains explicit; cancelling it preserves the prior electrode. The user is told to recalculate after applying specification changes and that finite search coverage does not establish universal impossibility. The tutorial describes the same workflow.

Verification includes all rejection categories, numeric total/reserved/usable length and shortfall, direct-entry and empty-coverage cases, named evidence aggregation and immutable hardware/constraints. A regression can load an external project with PLANNER_REACH_PROJECT without bundling user data. The supplied macaque case reproduces 17 depth rejections and a 6.28 mm shortfall at the reported point with a 20° grid limit. A packaged desktop check opens the exact reinforcement, total-length and chamber-height controls and verifies that cancelling a draft leaves usable length unchanged. Full workflow and packaged desktop regressions also pass.
