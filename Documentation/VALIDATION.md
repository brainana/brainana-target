# Validation and limits

Release automation checks version identity, TypeScript builds, planning and workflow regressions, packaged resources and a launch of the actual desktop app on each native platform. Validation JSON files record the platform, architecture, version and checks. Packaging checks include the app icon, demo CT checksum, runtime identity and bundled UI. Native launch checks load the NMT macaque demo and verify its CT and viewer controls.

Detailed local desktop regressions also cover manual chamber placement, depth-tested opacity, headpost settings, ear bars, image/maps/atlas display, portable save/reopen, planning/evaluation navigation and server shutdown. The tutorial regression checks the normal planner layout, visible side panels, practice, actual rendered opacity changes, state restoration and preservation of the user's autosave and undo history.

Passing software tests is not scientific, anatomical, mechanical or surgical validation. Template skull estimates, hardware approximations, fit/overlap calculations, coordinate calibration and measured electrode comparisons need independent assessment. The app is being shared as a very preliminary research prototype for exploration and feedback.
